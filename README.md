# SubmitSignal Form Guide

Free guidance for WordPress administrators reviewing ordinary WPForms Lite forms.
Publisher: Axtrel AI LLC. The guide assesses declared scope, explains user-reported
check evidence and describes supported WordPress installation steps.

It does not visit websites, inspect forms, access an account, install a connector,
submit an inquiry, send email, retry an uncertain submission or take payments.
Answers are processed transiently without application answer storage. AI providers
and hosting infrastructure process requests under their own disclosed policies.
Never provide passwords, pairing codes, visitor messages or account identifiers.

## Supported preparation formats

- Claude: .claude-plugin/plugin.json and .mcp.json; see docs/claude.md.
- Cursor: portable Agent Plugins plugin.json and mcp.json; see docs/cursor.md.
- Gemini CLI: root gemini-extension.json and GEMINI.md; see docs/gemini.md.
- GitHub Copilot/VS Code: examples/vscode/mcp.json contains the documented server entry.

Remote endpoint: https://getsubmitsignal.com/agent-mcp, anonymous Streamable HTTP.
Exactly three public tools: assess_form_compatibility, explain_form_check_evidence,
get_wordpress_setup_scope. No tool accesses the separate authenticated service.

## What evidence means

A scope match is based on supplied answers, not an inspection or proof of health.
Browser confirmation, WordPress processing acceptance, mail handoff and receipt at
one synthetic destination are separate observations. None guarantees delivery to
a customer's inbox, spam placement or CRM. Unknown evidence is not failure.
An uncertain submission may already have sent an inquiry; the owner must review
the exact attempt before another submission.
